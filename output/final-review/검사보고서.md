## 확인된 문제 및 수정

1. 설정 변경 직후 백업하거나 앱을 숨기면 0.5초 대기 설정이 빠질 수 있었다. 공용 flush로 설정·사진 기록·프로젝트·맵 메모를 반영하고, 백업/가져오기 전·visibility hidden·네이티브 pause에도 호출한다.
2. 기록 수정 직후 카테고리 삭제 시 대기 저장이 옛 카테고리를 되살릴 수 있었다. 삭제 전에 대기 저장을 완료하도록 수정하고 메모 글 보존 및 삭제 카테고리의 맵 메모 정리를 검사했다.
3. 폴더 파일 저장이 한 번 실패하면 이후 쓰기도 모두 실패한 Promise 체인에 묶였다. 다음 쓰기는 재시도 가능한 체인으로 바꾸고 load는 진행 중 쓰기가 끝난 뒤 읽도록 수정했다.
4. Android 패키지와 파일/백업 연결이 없었다. SDK 기본 WebView 셸과 앱 내부 파일 인터페이스, 사진/ZIP 선택, 백업 문서 저장 및 취소 처리, 시스템 영역/키보드 여백, 앱 뒤로가기·숨김 저장 처리를 추가했다. 새 라이브러리는 추가하지 않았다.

개발 서버 대신 `app/dist`의 자산을 로컬 HTTPS 출처로 제공해 숨김 Chromium 창에서 검사했다. 사용자 브라우저와 저장소를 공유하지 않았다. 상세 결과는 `checks.json`.

Android 어댑터 모의 검사는 실제 Java WebView 실행과 동일하지 않다. Java 소스는 Android SDK로 컴파일하고 APK 정적 구성과 서명을 검사했다.

## 미검증 및 남은 범위

- 연결된 Android 기기와 사용 가능한 AVD가 없어 APK 실제 설치/실행은 확인하지 못했다. Android 사진/문서 선택창, 시스템 뒤로가기, 키보드·인셋, 실제 손가락 제스처는 실기기 확인이 필요하다.
- 수백 장 사진·대용량 ZIP의 Android 메모리/성능과 프로세스 강제 종료는 검증하지 않았다. 파일 브리지는 base64 전달을 사용하므로 큰 백업의 메모리 사용량에 유의해야 한다.
- 저장 장치 용량 부족/권한 오류를 포함한 모든 저장 실패 상황을 복구하는 체계는 완성된 것으로 보지 않는다.
- 디자인 평가는 사용자 직접 확인 대상이며 시각 디자인을 재설계하지 않았다.
- 기존 Windows 설치 파일은 재생성하지 않았다. 이번 요청의 결과물은 웹 배포용 ZIP과 Android APK다.

산출물 크기와 SHA-256은 `build-hashes.json`에 기록한다. Android 빌드 방법과 저장 구조는 `app/android/README.md` 참고.
