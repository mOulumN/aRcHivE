## 안드로이드에서 동기화 폴더 고르기 (2026-11-05, 구현함·실기기 미확인)
- 구현 상태: 첫 실행에서 "이 폴더 사용(앱 내부) / 다른 폴더 고르기"를 고른다. 고른 폴더는 `TreeStore.java`가 `DocumentsContract`로 읽고 쓴다. 이미 앱 내부에 기록이 있으면 그대로 열린다. **미구현: 고른 뒤 폴더 바꾸기, 앱 내부 기록을 새 폴더로 옮기기.** 폴더 쓰기는 원자적이지 않아 `data.prev.json`이 유일한 직전 복사본이다.
- 아래는 구현 전 검토 기록.
- 사용자 제안: 컴퓨터처럼 안드로이드에서도 저장 폴더를 골라 Dropbox·OneDrive·Google Drive 폴더로 동기화.
- 현재: `app/android/src/local/archive/mobile/MainActivity.java`(206줄) 한 파일이 저장을 앱 내부 폴더(`getFilesDir()/archive`)에 하고, 웹과는 `archiveAndroid.request(json)` 하나로 통신(`readData`·`writeData`·`readFile`·`writeFile`·`deleteFile`·`exportBackup`). 웹 쪽 저장소(`folderStore`)는 컴퓨터와 같은 코드를 쓴다 → **웹 코드는 거의 안 바뀌고 Java 쪽 저장 위치만 바꾸면 된다.**
- 방법: 안드로이드 시스템 "폴더 고르기"(`ACTION_OPEN_DOCUMENT_TREE`)로 사용자가 폴더를 고르고, 영구 권한(`takePersistableUriPermission`)을 받아 `DocumentsContract`로 읽기·쓰기·지우기. 새 라이브러리 없이 기본 SDK로 가능(예상 100~150줄). 처음 실행 때 "앱 내부 / 폴더 고르기" 선택, 기존 앱 내부 데이터를 새 폴더로 옮기는 단계 필요.
- 주의(실기기 확인 필요): 클라우드 앱이 보여 주는 가상 폴더는 쓰기·이름 바꾸기(`data.json`을 임시 파일에 쓰고 교체하는 방식)가 불안정할 수 있어, **앱이 기기 안에 실제 폴더를 두고 그 폴더를 클라우드 앱이 동기화하는 방식**이 안전하다. 사진이 많으면 파일마다 시스템 호출이라 느릴 수 있다. 두 기기 동시 사용 시 `data.json` 충돌 가능(컴퓨터와 동일한 한계).
- 상태: 아직 구현하지 않음. 실기기에서 수정 APK 실행 확인이 먼저.

## 빌드 결과 (2026-11-04) — 실제 구현과 계획이 달라진 점
- **칠판은 react-konva 대신 HTML + SVG로 구현**: 메모 글쓰기(한글 입력)를 그림판 라이브러리 안에서 하기 어려워서. 사진은 `<img>`, 지목·선은 SVG, 메모는 실제 글상자. 기능은 계획과 같음.

- **여러 장 저장 시 진행 표시**(예: 저장 중… 3/20) 추가.
- **설치 파일 빌드는 프로젝트 경로가 너무 길면 실패**(윈도우 경로 길이 제한). 지금 프로젝트가 앱이 만든 임시 폴더라 경로가 길어서, 짧은 경로에 복사해 빌드했음. 보통 폴더로 옮기면 `npm run dist:win` 한 번으로 됨.
- 화면 라이브러리는 모두 `dist/`에 묶이므로 설치 파일에는 넣지 않음, 언어 파일은 한국어·영어만 → 설치 파일 125MB(대부분 Electron 실행 엔진).
