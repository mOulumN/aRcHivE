# 인수인계 — aRcHivE (2026-11-04 기준)

## 최신 인수인계 — 2026-11-05 (아래의 이전 상태보다 우선)

**현재 위치: APK 빈 화면 원인의 패키징 수정·검사 완료. 개인 서명 수정본 생성·재전달·실기기 확인 대기. 사용자는 현재 단계를 유지하고 기록을 마무리하라고 요청했다.**

- 웹/모바일 반응형 화면과 Android 기본 WebView 셸·저장 위치 선택(앱 내부 또는 SAF 폴더, `TreeStore.java`)·사진 선택·ZIP 백업 연결은 구현되어 있다(실기기 미확인). Capacitor는 도입하지 않았다. 새 라이브러리 금지 유지.
- 사진 기록은 카테고리와 무관하게 공유한다. 기준 태그와 맵 메모는 각 카테고리/프로젝트 범위별이다. 프로젝트 새 사진은 자동 배치하고 기존 고정 위치는 보존한다. 이 결정은 이미 확정되었으므로 아래 10·14장의 예전 질문을 다시 묻지 않는다.
- 모바일은 같은 웹 앱의 767px 이하 반응형이다. 목적지는 길게 누른 뒤 시트에서 탭, 확대는 핀치, 메모 선택 시 하단 전용 메뉴. 플로팅 창 접기/펼치기, 기본 고정 메모 글자 14px 및 설정 변경, 모든 스크롤바 숨김까지 반영되어 있다. 디자인은 사용자 직접 확인.
- 기존 웹/모바일 기능 검사는 57개 통과했으나 Android 어댑터 모의 검사는 실제 APK 실행 검증이 아니다. 사용자는 이전 개인 서명 APK 설치 성공·실행 빈 화면을 보고했다.
- 원인: Windows aapt2 자산 삽입 시 APK 하위 웹 경로가 역슬래시로 저장됨. `app/android/build.ps1`에서 직접 ZIP 삽입으로 `/` 경로를 사용하고 서명 전 경로·파일 검사 추가. Windows PowerShell 5 실행 및 UTF-8 BOM 유지.
- 수정 개발 서명 APK의 웹 파일 748개 원본 SHA-256 일치, 서명 v2/v3·정렬 통과. 수정본 실제 휴대폰 실행은 아직 미검증이며 해결 완료라고 단정하지 않는다.

### 이어서 작업할 때
- 먼저 IMPLEMENTATION.md의 최신 항목을 읽는다. 지금은 추가 구현·빌드·업로드를 자동 진행하지 않는다.
- 재개 시 개인 키로 재생성하고 동일 키 업데이트 설치 후 실행 확인. 명령은 IMPLEMENTATION.md에 있다. 키 파일 위치와 별칭은 로컬 전용 메모(`.local/개인메모.md`, git 제외)에 있다. 비밀번호는 사용자 콘솔에서만 입력하며 키·비밀번호를 업로드하지 않는다.
- 실기기 첫 화면, 사진 선택·저장 및 재실행, ZIP 내보내기/가져오기, 키보드·뒤로가기 확인은 남아 있다. 사용자 데이터 삭제나 앱 제거를 임의로 하지 않는다.
- 사용자 저장소에 시험 데이터를 넣지 않는다. 디자인 보존, 새 라이브러리 금지, 스크롤바 숨김 규칙 유지. 홈 재설계·검색/정렬·중단된 태그 추가 작업을 임의 재개하지 않는다.
- 아래 본문은 이전 기획과 작업 이력을 보존한 것이다. 과거 'Android 미구현', '웹 백업 UI 없음', '질문 필요' 등의 표현보다 이 최신 항목과 현재 코드가 우선한다.

## 1. 제품 한 줄
사진을 흰 칠판에 올리고, 사진의 특정 부분을 지목해 선으로 빼낸 뒤 옆에 생각을 적는 **개인용 아카이빙 앱**. 이름 **aRcHivE**(가칭, 대소문자 그대로).
기기 안에만 저장한다(서버·로그인 없음). 컴퓨터 설치 프로그램(Electron)이 먼저, 같은 화면 코드로 안드로이드는 그다음.

핵심 원칙(`기획/방향성.md`): 사진이 주인공 / 넣는다→적는다→저장한다가 막히면 안 됨 / 정형 칸(필수 입력) 없음 / 개별 기록(사진 1장 = 기록 1개) / 선 굵은 표·카드·서랍 같은 흑백 + 포인트색 하나.

## 3. 기술 스택과 실행
- Vite 8 + React 19 + TypeScript 7(`~7.0.2`), 라이브러리 `dexie`(브라우저 저장), `fflate`(ZIP 백업), `@fontsource/noto-sans-kr`. 상태 관리 라이브러리·라우터·UI 키트 없음(전부 직접).
- 글꼴 **Noto Sans KR 하나만**(앱에 포함, 인터넷 불필요).
- 칠판은 react-konva가 아니라 **HTML + SVG**(한글 입력 때문). 지금 `package.json`엔 konva가 없다.

| 할 일 | 명령 (`app/`에서) |
|---|---|
| 의존성 설치 | `npm ci` (처음 한 번. `node_modules` 없음) |
| 웹 미리보기 | `npm run dev` → 보통 http://localhost:5174 (이미 쓰고 있으면 5175). 또는 `.claude/launch.json`으로 미리보기 도구에서 실행 |
| 타입 검사 | `npx tsc -b` (먼저 통과해야 함) |
| 웹 빌드 | `npm run build` (tsc + vite, `dist/`) |
| 프로그램으로 실행 | `npm run app` |
| 설치 파일 | `npm run dist:win` → `app/release/aRcHivE-Setup-0.1.0.exe`. 경로가 너무 길면 실패(짧은 경로에 복사해 빌드). 코드 서명 없음 → 처음 설치 때 "알 수 없는 게시자" 경고 |
| 린트 | `npx oxlint` (기존 경고 다수 — 기준선일 뿐, 새로 늘리지만 말 것) |

**설치 파일 상태**: 13차에 만든 것이 `설치파일/`에 있다. **14차 변경(즐겨찾기 분리, 백업에 설정 포함, 카테고리로 끌어 넣기, 선택 확인 창 등)은 아직 설치 파일에 없다.** 설치 파일은 **사용자가 말할 때만** 다시 만든다(규칙).

## 4. 반드시 지킬 규칙 (`구현/규칙.md` 요약)
- 사진·기록은 서버로 안 보낸다. 화면 코드와 저장 코드를 분리한다(저장은 갈아끼울 수 있게).
- 웹 미리보기 저장(브라우저)엔 중요한 사진을 넣지 않는다(디자인 확인용, 백업 기능·설명 없음).
- 지목 위치는 사진 크기 대비 비율로 저장.
- **보조 설명 문구(안내 문장, 빈 화면 설명, 도움말 힌트)를 넣지 않는다.** 화면에는 이름·버튼·내용만.
- 강조색은 설정의 **테마 색 하나**(`--accent`)로 통일. 미리 정한 색 목록 금지, 브라우저 기본 색 고르기 창 금지(우리 색 고르기 창 사용).
- 화면 글자에 "계열" 금지 → **"카테고리"**.
- 입력창에 테마 색 포커스 테두리 금지. 제목 아래·구역 사이 꾸밈 구분선 금지(목록 칸 선·표 선은 예외).
- 늘어날 항목(카테고리·태그)은 전부 펼쳐 놓고 고르게 하지 않는다 → 검색되는 드롭다운(`MultiPick`). **예외**: 맵 "기준 태그" 창(사진 수와 함께 미리 보여 줌, 사용자 요청).
- **브라우저 기본 `prompt/confirm/alert` 금지** → `Ask.tsx`의 `useAsk / useConfirm / useNotice / useChoose`. (웹 미리보기는 기본 창이 안 뜨고 "아니오"로 처리되어 삭제가 조용히 취소됐었다.) 되돌리기 어려운 동작은 `danger` 확인 창, 문구는 "진짜 삭제할까요?".
- 왼쪽 제목 칸과 오른쪽 머리줄 높이는 `--head-h`(60px)로 맞춰 아래 선이 이어지게. "수정"은 연필 아이콘이 아니라 `(수정)` 글자.
- 수정할 때마다 설치 파일을 다시 만들지 않는다.

문구 톤: 짧은 한국어, 존댓말 안내(예: "남은 3장은 저장하지 않고 닫을까요?"). 영어 UI 문구·이모지 쓰지 않는다.

```ts
ProjectNote{id,text,x,y,w,entryIds[]}                            // 예전 entryId(하나)는 normalizeProject가 변환
PhotoMeta{id,name,type,ext,width,height,createdAt}
Snapshot {version:1,series,tags?,placements?,projects?,entries,photos,meta?}
```
- 카테고리 읽기는 항상 `categoriesOf(e)`, 태그는 `tagIdsOf(e)`. 카테고리를 바꿀 땐 `withCategories(e, ids)`.
- meta(키-값): `settings`(JSON), `map:main`(기준 태그 id 배열 JSON), `lastBackup`, `persist`. **백업에 들어가는 건 `settings`, `map:main`만.**
- Settings: `{boardBg,pageBg,accent,favorites:{boardBg,pageBg,accent,note}}`. 예전(favorites 배열)은 읽을 때 4곳에 복사.
- **브라우저 DB**: Dexie 버전 1(series,entries,photos,meta) → 2(tags) → 3(placements) → 4(projects). 개발자도구에서는 ×10인 40으로 보인다.
- **폴더 저장**: `data.json`에 위 Snapshot 필드 전부. 쓰기는 임시 파일→교체, 직전 내용은 `data.prev.json`.
- 새 필드는 **옵셔널**로 추가하고 읽을 때 변환한다(옛 데이터·백업 호환). 새 표는 Dexie 새 버전을 추가한다.

## 8. 주요 동작 규칙 (구현 사실)
- **맵**: 사진은 맵에 한 곳. 자기 태그 중 기준 목록에서 가장 앞선 태그의 묶음으로 감, 없으면 "기타", 기준이 비면 한 덩어리. 묶음 안은 나선형(사진 가로세로 비율 유지, 긴 변 112px), 묶음끼리는 줄지어(폭 1100px 줄바꿈). 이름표는 묶음당 하나, 고정 안 된 첫 사진 모서리에 걸침.
- **위치 고정**: 사진을 끌면 그 사진만 `Placement(main)`로 저장. 고정된 사진의 나선 자리는 **비워 둔다**(나머지가 안 움직이게). 화면 원점은 자동 배치와 무관한 상수(`MARGIN`) + 음수 고정 보정 → 놓은 자리에서 튀지 않음. 저장 좌표는 음수가 되지 않게 왼쪽·위로 못 끈다.
- **프로젝트**: 사진 위치는 `Placement(mapId=프로젝트 id)`. 새로 담은 사진은 격자 슬롯에 놓임. 기록 삭제 → 프로젝트에서도 빠지고 메모 연결 끊김, 프로젝트 삭제 → 위치도 삭제(사진은 그대로).
- **카테고리 삭제** → 안의 사진은 "카테고리 없음". **태그 삭제** → 사진에서 빠짐. 모두 앱 자체 확인 창.
- **꾹 눌러 끌기**: 0.45초 가만히(움직임 6px 이내) → 고스트. 짧게 누르면 기록 열기, 맵·프로젝트에서 누르고 바로 움직이면 위치 끌기(꾹 누르기 시작되면 위치 끌기는 `cancel`). 끌기 직후 click 무시는 60ms만.
- **카테고리 끌어 넣기 분기**: 특정 카테고리 화면에서 출발(`fromCategory`)해 다른 카테고리에 놓으면 `useChoose`로 옮기기/추가하기/취소. 출발이 전체·카테고리 없음·프로젝트면 묻지 않고 추가. 같은 카테고리·프로젝트에 놓으면 변화 없음.
- **선택 창 칸**: "고른 사진 **전부**가 속한" 프로젝트/카테고리만 선택된 것으로 보임. 다시 누르면 전부에서 뺌.

  | Ctrl+휠 확대(맵·프로젝트), 칠판은 휠만 | **핀치 확대**(칠판에는 아직 없음), 두 손가락 이동 |

- **좁은 창에서 이미 깨지는 곳**: 창 너비 약 435px에서 `.pane-head` 버튼이 3줄로 접혀 60px 이어진 선이 무너진다(`flex-wrap: wrap`). 폰에서는 머리줄을 한 줄로 고정하고 나머지는 아래 바/더보기로.

## 12. 시험·작업 요령 (함정 모음)
**사용자 실제 데이터가 있는 곳**: 웹 미리보기를 연 내장 브라우저의 `http://localhost:5175`(또는 5174) 저장소에 사용자 사진 17장(카테고리 아카이브·데코·픽셀·게임·UI, 프로젝트 "픽셀/독서")이 있다. **여기에 시험 데이터를 넣거나 지우지 말 것.** 시험은 **다른 포트(예: `npx vite --port 5199 --strictPort`)의 새 탭**에서 한다(브라우저 저장은 주소·포트별로 분리됨). 끝나면 `indexedDB.deleteDatabase('aRcHivE')`, 탭 닫기, 서버 종료. 사용자가 시험 탭을 직접 누르고 있을 수도 있으니 스크립트는 처음부터 화면을 이동하게(홈이면 "전체" 눌러 보관 화면으로) 쓴다.

**내장 브라우저 도구 특성**
- 기본 `confirm/alert`는 뜨지 않고 취소로 처리됨(→ 앱 자체 창).
- `computer` 도구의 좌표는 스크린샷 기준이고 **실제 창 크기(`innerWidth`)와 배율이 다르다**: `도구좌표 = clientX / (innerWidth / 스크린샷가로)`. 창을 바꾸면 배율도 바뀐다. 요소 위치는 JS의 `getBoundingClientRect()`로 구한 뒤 변환해 `left_click_drag`로 끌면 실제 마우스 시험이 된다.
- 도구의 끌기는 눌렀다-움직임-뗌이 **즉시** 일어난다 → **"꾹 누르기"(0.45초)는 실제 마우스로 시험 불가**. `PointerEvent`를 합성해 `pointerdown` → 650ms 대기 → `window`에 `pointermove`/`pointerup`을 쏘는 방식으로 확인했다(`setPointerCapture`는 try/catch로 감쌈).
- 스크린샷이 한 박자 늦게 갱신될 수 있으니 DOM 값(`offsetLeft`, DB 내용)으로 검증하는 게 확실하다. IndexedDB는 `indexedDB.open('aRcHivE')`로 직접 읽고 쓸 수 있다(새 표를 쓰는 트랜잭션에 표 이름을 **빠뜨리면** 일부만 저장되니 주의).
- React 입력(controlled)에 값을 넣으려면 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` 후 `input` 이벤트.
- 드롭다운(`MultiPick`)은 고른 뒤에도 열려 있고, 바깥 `pointerdown`에 닫힌다. 코드로 `.click()`만 하면 다른 드롭다운이 안 닫혀 입력이 엉뚱한 칸으로 갈 수 있다.

**개발 중 겪은 버그에서 얻은 규칙**
- `reload`가 겹치면 태그 변환이 중복 생성 → 한 줄로 세움.
- 상태 함수는 렌더 시점 값을 캡처 → 방금 만든 것을 바로 쓰는 호출은 인자로 넘김.
- CSS specificity 동률이면 뒤 규칙이 이김(z-index 사건).
- 끌기 직후 click 무시 표시를 오래 두면 키보드 click을 삼킴 → 60ms.
- 정규식으로 CSS를 일괄 치환하다 규칙 일부가 깨진 적 있음 → CSS는 편집 도구로 정확히 바꾸고 `tsc` + 눈으로 확인.
- Windows 경로 길이 제한으로 설치 파일 빌드가 실패할 수 있음.

**검증 습관**: 변경마다 ① `npx tsc -b` ② 별도 포트에서 실제 동작(가능하면 실제 마우스) ③ DB 값 확인 ④ `npm run build` ⑤ `구현/IMPLEMENTATION.md`에 "확인한 것 / 못 한 것"을 구분해 기록.
