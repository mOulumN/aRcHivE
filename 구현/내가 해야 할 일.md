## 새 서명 키 만들기 (공개 배포용, 이름 정보 없이)
지금 앱을 설치해 쓰는 사람은 사실상 나뿐이라, **공개 전에 새 키로 바꾸는 비용이 가장 작다.** (키가 바뀌면 이미 설치된 앱 위에 덮어 설치되지 않으므로, 내 폰은 백업 ZIP을 내보낸 뒤 앱을 지우고 새 APK를 설치해 가져온다.)
- [ ] 내 PowerShell에서 **직접** 실행(비밀번호는 콘솔에서 내가 입력, 어디에도 적지 않기). 이름 칸은 아이디만:
  ```powershell
  keytool -genkeypair -v -keystore "$env:USERPROFILE\Documents\앱서명키\archive-release-public.jks" -alias archive -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=mOulumN, C=KR"
  ```
  - 경로는 **그대로 복사해서 실행**하면 된다(`$env:USERPROFILE`이 내 사용자 폴더로 바뀐다). `<...>` 같은 꺾쇠 표시는 "직접 바꿔 넣으라"는 자리 표시이므로 그대로 실행하면 안 된다
  - `Documents\앱서명키` 폴더가 없으면 먼저 `New-Item -ItemType Directory -Force "$env:USERPROFILE\Documents\앱서명키"`
  - 인증서 이름 칸(`CN=`)은 공개된다. 저작권자 표시와 같은 `mOulumN`을 썼다
  - 만든 뒤 확인: `keytool -list -v -keystore "$env:USERPROFILE\Documents\앱서명키\archive-release-public.jks"` (비밀번호 입력 후 "소유자"에 `CN=mOulumN, C=KR`만 보이면 된다. "SHA-256" 지문은 README에 적을 값)
- [x] 새 키 파일 만들기 완료(`Documents\앱서명키\archive-release-public.jks`)
- [ ] `keytool -list -v`로 소유자가 `CN=mOulumN, C=KR`인지 확인(비밀번호는 내가 직접 입력)
- [ ] **암호 건 백업 만들기**: 7-Zip은 설치되어 있다. 아래를 내 PowerShell에서 실행하고, 암호를 두 번·한 번 입력(화면에 안 보임)하면 압축·검증까지 끝난다. 암호는 AI가 보지 않는다.
  ```powershell
  powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\aRcHivE\.local\키백업압축.ps1"
  ```
- [ ] 만들어진 `archive-release-public.7z`를 **USB와 Google Drive(공유 "제한됨")에 복사**. 압축 암호와 키 비밀번호는 키·압축 파일과 **다른 곳**(비밀번호 관리자나 종이)에 적어 둔다. 저장소에는 절대 넣지 않는다
- [ ] 새 키로 APK 다시 서명: 명령은 `구현/IMPLEMENTATION.md`, 실제 경로는 `.local/개인메모.md`. 이때 AI에게 비밀번호를 알려 주지 않는다
- [ ] 새 키의 인증서 지문(SHA-256)을 README에 적어 "이 지문으로 서명된 APK만 공식"이라고 안내 (이름 정보가 없는 키라 공개해도 안전)
