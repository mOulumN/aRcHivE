# 배포 설정 — aRcHivE

`deploy` 스킬이 읽는 이 앱의 배포 방법이다. 비밀번호·키 내용은 적지 않는다(키 위치는 `.local/개인메모.md`).

## 앱 종류와 배포 형태
- 스택: Vite + React + TypeScript 웹 앱을 감싼 **Electron(Windows)** 과 **직접 만든 Android WebView 셸**(Gradle·Capacitor 없음).
- 배포 형태(v0.1.0부터 같은 구성):
  | 형태 | 만드는 법 | 결과물 |
  |---|---|---|
  | Android 릴리즈 APK | `app`에서 `npm run build` → Windows PowerShell 5로 `app/android/build.ps1 -Keystore <공개용 키> -KeyAlias archive` (비밀번호는 사용자가 콘솔에 직접 입력) | `설치파일/aRcHivE-Android-<버전>-release.apk` |
  | Windows 설치 EXE | `app`에서 `npm run build` 후 `npx electron-builder --win nsis` | `app/release/aRcHivE-Setup-<버전>.exe` |
- 만들지 않는 것: 디버그(개발 키) APK — 서명이 달라 설치된 앱 위에 덮어 설치되지 않아 혼란만 준다. 웹 zip — 웹은 시연용(`구현/공개범위.md`).

## 버전
- 버전 위치: `app/package.json`의 `version`(EXE 이름에 쓰임), `app/android/build.ps1`의 `--version-code`·`--version-name`과 APK 파일 이름.
- 마지막 릴리즈: **v0.1.2** (2026-11-06)

## 서명 키
- 있음. **공개용 키** `archive-release-public.jks`, 별칭 `archive`, 인증서 `CN=mOulumN, C=KR`, SHA-256 `323a29eb6fcc315a507dc2f62b39e514786272058e1bbee7ceace45703050380`.
- 파일 경로·백업 경로는 `.local/개인메모.md`. 비밀번호는 사용자만 안다(콘솔 입력).
- 개인 키 `archive-release.jks`(실명 인증서)로는 만들지 않는다. 설치된 앱과 서명이 달라 업데이트가 안 된다.

## 배포 기준
- `구현/공개범위.md`와 `.gitignore`를 따른다(사용자가 정한 기준). 요약: 앱 소스·설정·`기획/`·`구현/` 문서·개발 기록은 올린다. 서명 키·`.env`·`.local/`·`레퍼런스/`·설치 파일·빌드 결과·`.vite/` 캐시는 올리지 않는다.
- 새로 생긴 파일 중 기준으로 판단이 안 되는 것은 올리지 않고 보고한다.

## 구글 드라이브 저장
- 저장함. 폴더: 내 드라이브 `개발/아카이브/` (동기화 폴더 `G:\내 드라이브\개발\아카이브`). 최신 파일만 바로 아래, 이전 버전은 `이전버전/`.
- 참고: 드라이브에서 APK를 받으면 "악성 앱"으로 막힐 수 있다(새 개발자·새 서명 앱이라 구글 기록이 없음). 본인 휴대폰에는 USB 설치를 권한다.
