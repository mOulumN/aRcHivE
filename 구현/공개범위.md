# 공개 범위 — GitHub 공개 저장소에 올리는 것과 올리지 않는 것

공개 저장소는 올린 내용이 **기록(history)에 영구히 남는다.** 한 번 올린 비밀·개인 정보는 파일을 지워도 되돌릴 수 없다.
그래서 "소스와 문서"만 올리고, 나머지는 `.gitignore`가 막는다. 규칙이 바뀌면 이 문서와 `.gitignore`를 함께 고친다.

## 올려도 되는 것
| 위치 | 내용 |
|---|---|
| `app/src/`, `app/electron/`, `app/public/` | 앱 소스 |
| `app/android/` (소스·매니페스트·`res/`·`build.ps1`·README) | 안드로이드 셸 소스와 빌드 스크립트 |
| `app/package.json`, `package-lock.json`, `tsconfig*.json`, `vite.config.ts`, `index.html`, `.oxlintrc.json` | 설정 |
| `기획/`, `구현/`, `CLAUDE.md`, `.claude/launch.json`, `.gitignore` | 기획·구현 문서, 개발 설정 |
| `output/`(점검 보고서·검사 기록), `app/vite-preview*.log` | **개발 기록.** "내가 만들어 온 과정"을 남기려고 올린다. 올리기 전에 개인 경로가 없는지 확인하고, 있으면 `<프로젝트 폴더>`로 바꾼다(원본은 `.local/`) |
| (추가 예정) `README.md`, `LICENSE` | 소개, 사용 조건 |

## 올리면 안 되는 것 (`.gitignore`가 막음)
| 대상 | 이유 |
|---|---|
| `*.jks` `*.keystore` `*.pem` `*.p12` `*.pfx` `*.key` `.env*` | **서명 키·비밀.** 새어 나가면 남이 내 이름으로 앱을 서명·업데이트할 수 있다. 키는 저장소 밖에 보관하고 별도로 백업한다 |
| `.local/` | 개인 경로, 키 위치, 개인 링크 등 로컬 메모 |
| `레퍼런스/` | 다른 사이트에서 가져온 이미지(남의 저작물). 설명 문서 `기획/레퍼런스분류.md`만 올린다 |
| `설치파일/`, `*.exe`, `*.apk`, `*.idsig`, `*.zip`, `인수인계/` | 큰 산출물(GitHub은 파일당 100MB 한도). **설치 파일은 GitHub "Releases"에 올린다.** `인수인계/`의 스냅샷 zip에는 레퍼런스 이미지(남의 저작물)가 들어 있어 올리지 않는다 |
| `node_modules/`, `app/dist/`, `app/release/`, `app/android/build/` | `npm ci` / 빌드로 다시 만들어지는 것(중간 APK·개발 키 포함) |
| 사용자 사진·앱 데이터 | 앱은 사용자 기기에만 저장하므로 저장소에 있을 일이 없다. 시험용 사진도 넣지 않는다 |

## 문서에 개인 정보를 적지 않는 방법
- 내 컴퓨터 경로, 서명 키 위치, 개인 링크(Drive 등)는 문서에 쓰지 말고 `.local/개인메모.md`(git 제외)에 적는다.
- 문서에는 `<프로젝트 폴더>`, `<개인 서명 키 파일>` 같은 자리 표시를 쓴다.
- 비밀번호는 어디에도 적지 않는다(콘솔에서만 입력).

## 처음 올리기 전 체크리스트
1. **커밋에 쓰는 이메일을 GitHub의 noreply 주소로 바꾼다.** 커밋은 작성자 이메일이 공개된다. (GitHub 설정 → Emails → "Keep my email addresses private" 후 `<숫자>+<아이디>@users.noreply.github.com`) — `git config user.email ...`
2. `git status`로 올라갈 파일 목록을 눈으로 확인한다(처음 78개, 가장 큰 파일 약 180KB).
3. `git log -p`/`git diff --cached`에서 비밀번호·키·개인 경로가 없는지 `grep`으로 한 번 더 찾는다.
4. `LICENSE`와 `README.md`를 넣는다. 저작권자 이름 표기는 하지 않기로 했으므로(`기획/결정.md`), 이름 칸이 필요 없는 라이선스를 고르거나 GitHub 아이디를 쓴다. README에는 "웹은 시연용, 실제 사용은 컴퓨터 프로그램·안드로이드 앱"을 적는다.
5. 먼저 **비공개(private)** 저장소로 올려 화면에서 파일 목록을 확인한 뒤, 이상 없으면 공개로 바꾼다.
6. 설치 파일(APK·EXE)은 Releases에 올린다. 개발 키로 서명한 APK는 "서명이 다른 앱 위에 덮어 설치되지 않는다"는 점을 릴리스 설명에 적는다.

## 웹 버전의 위치 (결정)
- **웹은 시연용으로만 쓴다. 웹 전용 백업 화면은 만들지 않는다.** 브라우저에 저장된 데이터는 "사이트 데이터 삭제"로 지워질 수 있고(PWA로 설치해도 같은 저장소), 영구 저장 요청은 자동 삭제만 막기 때문이다.
- 그래서 **실제로 쓰는 사람에게는 컴퓨터 프로그램(폴더 저장)과 안드로이드 앱(앱 내부 또는 고른 폴더 저장 + ZIP 백업)을 안내한다.** 웹이 시연용이라는 안내는 앱 화면(보조 설명 문구 금지 규칙)이 아니라 **README**에 적는다.

## 서버·동기화 (결정)
- 서버는 지금 만들지 않는다. 사용자가 늘면 그때 정한다. 만들게 되면 **별도 저장소**로 두어 비밀·라이선스를 따로 관리한다.
- 서버 없이도 컴퓨터끼리는 저장 폴더를 Dropbox·OneDrive·Google Drive 폴더로 고르면 동기화된다. `data.json` 하나에 카테고리·태그·메모·프로젝트·위치·설정이 모두 들어 있어서 사진과 함께 그대로 따라간다(동시에 두 기기에서 쓰면 충돌 가능). 안드로이드 앱도 처음 실행 때 폴더(드라이브 폴더 포함)를 고를 수 있다(실기기 미확인). 앱 내부 저장을 고르면 백업 ZIP으로 옮긴다.
